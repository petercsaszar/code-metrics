## ?? Customization Examples

### 1. Analyze Only Model Projects
```yaml
script:
  - dotnet analyzer-tool/CodeMetricsAnalyzer.dll \
      analyze TicTacToeGame.Model.Basic/TicTacToeGame.Model.Basic.csproj \
      --report-output ${ANALYZER_OUTPUT}
```

### 2. Set Quality Gates
```yaml
script:
  # ... analysis commands ...
  - |
    ISSUES=$(jq '.Metrics[-1].TotalIssues' ${ANALYZER_OUTPUT}/history.json)
    ERRORS=$(jq '.Metrics[-1].IssuesBySeverity.Error // 0' ${ANALYZER_OUTPUT}/history.json)
    
    if [ "$ERRORS" -gt 0 ]; then
      echo "? Found $ERRORS errors - pipeline failed"
      exit 1
    fi
    
    if [ "$ISSUES" -gt 50 ]; then
      echo "??  Warning: $ISSUES issues exceed threshold of 50"
    fi
```

### 3. Schedule Weekly Analysis
```
GitLab ? CI/CD ? Schedules ? New Schedule

Description: Weekly code quality check
Interval: 0 0 * * 0  (Every Sunday at midnight)
Target: master
Variables: (none needed)
```

### 4. Notify on Degradation
```yaml
script:
  # ... analysis commands ...
  - |
    CURRENT=$(jq '.Metrics[-1].TotalIssues' ${ANALYZER_OUTPUT}/history.json)
    PREVIOUS=$(jq '.Metrics[-2].TotalIssues' ${ANALYZER_OUTPUT}/history.json)
    CHANGE=$((CURRENT - PREVIOUS))
    
    if [ "$CHANGE" -gt 10 ]; then
      # Send notification (Slack, email, etc.)
      echo "?? Alert: Issues increased by $CHANGE!"
    fi
```

## ?? Best Practices

### 1. Monitor Both Metrics and Coverage
```
High Coverage + Low Issues = Excellent Quality ?
High Coverage + High Issues = Tests exist, but code needs work ??
Low Coverage + Low Issues = Clean code, but needs tests ??
Low Coverage + High Issues = Technical debt accumulating ?
```

### 2. Set Realistic Goals
```
Phase 1: Establish baseline
Phase 2: Stabilize (no increase)
Phase 3: Gradual improvement (-5% per month)
Phase 4: Maintenance (stay below threshold)
```

### 3. Review Regularly
```
Daily:   Check trend indicator on commits
Weekly:  Review history charts
Monthly: Analyze patterns, set new goals
```

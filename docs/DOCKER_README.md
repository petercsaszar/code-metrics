# Docker-Based Code Metrics Analyzer

This Docker image provides a **turnkey solution** for analyzing student projects from GitLab. Everything is pre-installed (MSBuild, cloc, .NET SDK, Python) inside the container—no local setup required.

## Quick Start: Using student_container_analyzer.py

The easiest way to analyze all student projects is to use the `student_container_analyzer.py` script:

```bash
# 1. Build the Docker image
docker build -t code-metrics-analyzer -f docker/Dockerfile .

# 2. Run the script (from project root)
python -m bulk_analyzer.student_container_analyzer \
  --config bulk_analyzer/config.yml \
  --image code-metrics-analyzer \
  --output-dir ./analysis_outputs \
  --processed-commits ./processed_commits.json \
  --concurrency 4
```

This script will:
- Fetch all projects from your configured GitLab group/subgroup
- Run Docker containers in parallel to analyze each project at milestone commits
- Collect JSON results and HTML reports from each container
- Generate a `summary.json` with completion status

### Output Files

After completion, check `./analysis_outputs/`:
- `analysis_results_1.json`, `analysis_results_2.json`, etc. — per-milestone raw metrics
- `*.html` — HTML reports generated by CodeMetricsAnalyzer (one per project/milestone combination)
- `summary.json` — completion status for each project

### Command-Line Options

```
--config         Path to config.yml (default: config.yml)
--image          Docker image name (default: from config.docker.image)
--output-dir     Host directory for outputs (default: ./analysis_outputs)
--processed-commits  Host file to persist analyzed commits (optional)
--concurrency    Number of parallel container runs (default: 2)
```

## Advanced: Manual Docker Invocation

If you prefer to run Docker containers manually instead of using the Python script:

### 1. Build the Docker Image

```bash
# Basic build (without Unity support)
docker build -t code-metrics-analyzer -f docker/Dockerfile .

# Build with optional Unity CLI support
docker build \
  -t code-metrics-analyzer \
  --build-arg UNITY_DOWNLOAD_URL="https://example.com/unity-installer.sh" \
  -f docker/Dockerfile .
```

### Optional: Getting a Unity Installer URL

If you need Unity support, you have a few options:

**Option 1: Use Unity from the host machine (recommended)**
This avoids adding several GB to the Docker image. The entrypoint script automatically reads `config.yml` and uses the `analyzer.unity_path` setting if you mount the host Unity directory.

```bash
# 1. In your config.yml, set the container path where you'll mount Unity:
# analyzer:
#   unity_path: "/mnt/unity/Editor/Unity"

# 2. Run with a mount (on Linux)
docker run --rm \
  -v /path/to/host/Unity:/mnt/unity:ro \
  -v $(pwd)/config.yml:/opt/bulk_analyzer/config.yml:ro \
  -v $(pwd)/analysis_outputs:/outputs \
  code-metrics-analyzer \
  --report-output /outputs

# On Windows:
docker run --rm \
  -v "C:/Program Files/Unity/Hub/Editor/2022.3.0f1":/mnt/unity:ro \
  -v $(pwd)/config.yml:/opt/bulk_analyzer/config.yml:ro \
  -v $(pwd)/analysis_outputs:/outputs \
  code-metrics-analyzer \
  --report-output /outputs
```

The container will automatically detect the mounted path and log whether it found Unity. No need to pass `UNITY_PATH` as an environment variable!

For `student_container_analyzer.py`, just ensure your `config.yml` has `analyzer.unity_path` set and the Docker runtime on your host has the ability to mount volumes. The script will pass them through automatically.

**Option 2: Host a custom installer script**
Create a shell script that downloads and installs Unity Editor for Linux, then host it on a web server:

```bash
#!/bin/bash
# install_unity.sh
set -e
apt-get update
apt-get install -y --no-install-recommends \
    libssl-dev \
    libffi-dev \
    build-essential
# Download Unity Editor for Linux (example for 2022.3 LTS)
cd /tmp
wget https://netstorage.unity3d.com/unity/[version]/LinuxEditorInstaller/Unity.tar.gz
tar -xzf Unity.tar.gz
./Editor/install-dependencies
echo "Unity installed"
```

Then host this script and pass its URL:
```bash
docker build -t code-metrics-analyzer \
  --build-arg UNITY_DOWNLOAD_URL="https://your-server.com/install_unity.sh" \
  -f docker/Dockerfile .
```

**Option 3: Skip Unity and set UNITY_PATH=""**
If you don't need Unity support (for C# projects only), leave `UNITY_PATH` empty in your config.yml and omit the build-arg.

**Note**: Option 1 (host mount) is recommended because it keeps the Docker image small and fast to build. Unity is very large; mounting from the host avoids the overhead of downloading and installing it in the container on every build.

### 2. Run the Analyzer (Manual)

Mount your config file, outputs directory, and (optionally) a persistent processed-commits file:

```bash
docker run --rm \
  -v /path/to/config.yml:/opt/bulk_analyzer/config.yml:ro \
  -v /path/to/outputs:/outputs \
  -v /path/to/processed_commits.json:/processed_commits.json \
  -e REPORT_OUTPUT=/outputs \
  -e PROCESSED_COMMITS_PATH=/processed_commits.json \
  code-metrics-analyzer \
  --report-output /outputs \
  --processed-commits-file /processed_commits.json
```

### 3. View Results

After the run completes, check `/path/to/outputs`:
- `analysis_results_1.json`, `analysis_results_2.json`, etc. – per-milestone raw results
- `*.html` – HTML reports generated by CodeMetricsAnalyzer
- `processed_commits.json` – tracks which commits have been analyzed (in case of re-runs)

### 4. Example: Full Manual Run with Persistent State

```bash
# First run—analyzes all milestones for all projects
docker run --rm \
  -v $(pwd)/config.yml:/opt/bulk_analyzer/config.yml:ro \
  -v $(pwd)/analysis_outputs:/outputs \
  -v $(pwd)/processed_commits.json:/processed_commits.json \
  code-metrics-analyzer \
  --report-output /outputs \
  --processed-commits-file /processed_commits.json

# Second run—only analyzes new/changed projects (skips already-processed commits)
docker run --rm \
  -v $(pwd)/config.yml:/opt/bulk_analyzer/config.yml:ro \
  -v $(pwd)/analysis_outputs:/outputs \
  -v $(pwd)/processed_commits.json:/processed_commits.json \
  code-metrics-analyzer \
  --report-output /outputs \
  --processed-commits-file /processed_commits.json

# Force re-analysis of all commits
docker run --rm \
  -v $(pwd)/config.yml:/opt/bulk_analyzer/config.yml:ro \
  -v $(pwd)/analysis_outputs:/outputs \
  code-metrics-analyzer \
  --report-output /outputs \
  --force
```

## Configuration

The container uses `config.yml` to determine:
- GitLab API URL, token, and group/subgroup IDs
- Milestone keywords to search for
- Repository clone directory (inside container: `/repos`)
- Analyzer paths (project file, MSBuild, etc.)

Ensure your `config.yml` has `analyzer.msbuild_dir` and `analyzer.unity_path` set appropriately, or leave these empty to use defaults from the container. For example:

```yaml
analyzer:
  solution_dir: "../CodeMetricsAnalyzer"
  project_dir: "../CodeMetricsAnalyzer/CodeMetricsAnalyzer/"
  msbuild_dir: ""  # Use system dotnet
  project_file: "CodeMetricsAnalyzer.csproj"
  unity_path: "/mnt/unity/Editor/Unity"  # Set to container path where host Unity is mounted (or empty to skip)
  unity_version: "6000.1.15f1"
```

**Important**: When using Unity:
1. Set `unity_path` to the **container path** where you'll mount the host Unity directory (e.g., `/mnt/unity/Editor/Unity`)
2. Mount the host Unity directory at build/run time using `-v /host/unity:/mnt/unity:ro`
3. The entrypoint script will automatically detect and use this path from config.yml

## Environment Variables

Inside the container:
- `ANALYSIS_MODE` – `milestone` (default) analyzes each configured milestone commit via `bulk_analyzer.analyzer`; `latest_snapshot` instead checks out HEAD of each project's default branch via `bulk_analyzer.latest_snapshot_analyzer`, skipping milestone lookup entirely
- `ANALYZER_CONFIG` – path to config.yml (default: `/opt/bulk_analyzer/config.yml`)
- `REPORT_OUTPUT` – directory for JSON and HTML outputs (default: `analysis_results.json`)
- `PROCESSED_COMMITS_PATH` – file to track analyzed commits (default: `processed_commits.json`)
- `CLOC_PATH` – path to cloc binary (default: `cloc`)
- `UNITY_PATH` – path to Unity Editor executable (auto-detected from config.yml if set, or override at runtime)

**Note**: The entrypoint script automatically reads `analyzer.unity_path` from config.yml and sets `UNITY_PATH` if not already set. You can still override by explicitly setting `-e UNITY_PATH=<path>`.

Example — analyze the latest commit on each project's default branch instead of milestones:

```bash
docker run --rm \
  -v "$(pwd)/reports:/app/reports" \
  -e GITLAB_TOKEN=glpat-xxxxxxxxxxxxxxxxxxxx \
  -e GITLAB_URL=https://gitlab.example.com \
  -e GITLAB_GROUP_ID=42 \
  -e ANALYSIS_MODE=latest_snapshot \
  code-metrics-analyzer
```

## Features

- **Pre-installed**: MSBuild (via .NET SDK 8.0), cloc, git, Python 3, mono
- **Optional Unity**: Pass `--build-arg UNITY_DOWNLOAD_URL=<url>` at build time to include Unity Editor CLI
- **Incremental Analysis**: Persists `processed_commits.json` to avoid re-analyzing the same commits on subsequent runs
- **HTML Reports**: Generates interactive HTML reports via CodeMetricsAnalyzer for each analysis run
- **GitLab Integration**: Clones and analyzes repos directly from GitLab using credentials in `config.yml`

## Notes

- **Recommended**: Use `python -m bulk_analyzer.student_container_analyzer` to orchestrate analysis of all projects at once with parallel processing and automatic HTML collection.
- The container runs `analyzer.py` which processes all milestones defined in your GitLab group/subgroup.
- For each project/milestone combination, the analyzer generates metrics JSON and HTML reports (via CodeMetricsAnalyzer).
- Repo clones are stored inside the container's temporary filesystem; each run uses the mounted config to re-clone or fetch fresh commits.
- If you need to persist repo clones between runs, mount a host directory to the container's repo clone path (e.g., `-v /tmp/student_repos:/repos`).

## Troubleshooting

**student_container_analyzer exits with errors**
- Check that the Docker image name is correct: `docker image ls | grep code-metrics-analyzer`
- Verify `config.yml` is readable and contains valid GitLab credentials
- Check Docker daemon is running: `docker ps`

**Container exits with "Repository not found"**
- Check GitLab API token in `config.yml`
- Verify group/subgroup IDs are correct
- Ensure the token has read permissions for the projects
- Run manually to see detailed error output

**Cloc not found**
- Verify the Docker image was built successfully
- Check that `/usr/bin/cloc` exists in the container: `docker run code-metrics-analyzer which cloc`

**No HTML reports generated**
- Verify CodeMetricsAnalyzer ran successfully (check stderr output from container)
- Ensure MSBuild can find and build the `.sln` files
- Check that output directory is writable

**Unity project not analyzed**
- Set `UNITY_PATH` in config or pass a URL to Unity installer at build time
- Ensure the `UNITY_VERSION` in config matches the desired Editor version
